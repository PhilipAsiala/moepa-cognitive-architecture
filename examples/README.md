# Examples: MOEPA in Practice

These walkthroughs are for leaders and architects who need to see how a decision changes when the five layers and the Data Substrate are owned. The scenarios are public-sector (benefits, eligibility, verification). The ownership questions apply to any organization that must explain a score or a denial.

Predictive work in these examples is the confidence score or the intake score. Generative work is the explanation a caseworker, constituent, or reviewer can read. Both point at the same owned record.

| Scenario | File | Layers |
|---|---|---|
| Third-party income verification | [income-verification.md](income-verification.md) | All 5 + Substrate |
| AI project intake scoring | [project-intake-scoring.md](project-intake-scoring.md) | All 5 + Substrate |
| Benefits eligibility determination | [benefits-eligibility.md](benefits-eligibility.md) | All 5 + Substrate |

Each scenario walks through the five MOEPA disciplines as business outcomes: trusted data, shared meaning, verifiable truth, governed action, and enforced values. There is no implementation code in these files.

Architects implementing these patterns should also follow [architectural evolution guidelines](../docs/MOEPA-Architectural-Governance-and-Evolution-Guidelines.md).
