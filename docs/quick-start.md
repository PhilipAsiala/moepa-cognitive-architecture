# Quick Start

## What This Is

This page is a reading path for leaders and architects evaluating the **MOEPA Cognitive Architecture**, a draft frame for deciding what an organization must own in an AI system.

The architecture maps three jobs onto five layers. **Cognition** is knowing (Metrology, Ontology, Epistemology: measurement, shared definitions, and verification). **Affect** is valuing (Axiology: value and priority constraints). **Conation** is acting (Praxeology: workflows and human checkpoints). Those layers read and write an organization-owned **Data Substrate** (how knowledge is stored), and **Agents** are the engine that consumes that substrate to do the work.

The practical effect is an intake decision: GO, CONDITIONAL GO, or NO-GO, with ownership stated before tools are chosen.

See the [Glossary](glossary.md) and [Pitch Strategy](pitch-strategy.md) for term definitions. The pitch strategy §0 readability standard applies to every page in this repository.

## What This Repository Is Not

This repository describes the draft MOEPA Cognitive Architecture for evaluating AI priorities and governance decisions. It is intended for discussion, refinement, and review — not as a production implementation guide.
